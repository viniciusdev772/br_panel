CLI do BR Panel

Tudo o que o painel faz pode ser feito no terminal do servidor com o comando brpanel: publicar apps, ver logs, mudar variáveis, domínios, bancos de dados e backups. São {{.CLICount}} comandos, com respostas curtas e iguais em todos eles, pensados para pessoas e para agentes de IA.

sudo brpanel status
sudo brpanel apps list
sudo brpanel apps deploy minha-app --wait

O comando fala com o painel por um socket local (/var/lib/brpanel/brpanel.sock) que só o root abre. Não há senha, token nem variável de ambiente para configurar, e nada fica exposto na rede. Se a pasta de dados não for a padrão, use --data PASTA.

Acesso remoto (do seu computador)

Controle este servidor de qualquer lugar, no Linux, macOS ou Windows. São três passos: instalar a CLI, criar um token aqui e entrar com o endereço do servidor.

1. Instalar (no seu computador, não no servidor):

curl -fsSL https://raw.githubusercontent.com/viniciusdev772/br_panel/main/scripts/install-cli.sh | sh
irm https://raw.githubusercontent.com/viniciusdev772/br_panel/main/scripts/install-cli.ps1 | iex

A primeira linha serve para Linux e macOS; a segunda, para o PowerShell do Windows. O instalador confere a soma SHA-256 e não pede administrador.

3. Entrar (no seu computador; o token é pedido sem aparecer na tela):

brpanel login {{.PanelHost}}
brpanel status

Use o endereço com SSL (o domínio do painel). Com só o IP o token viaja sem criptografia, e a CLI avisa e pede confirmação (--allow-http em scripts). Para voltar ao servidor local: brpanel logout. O login fica só no seu computador (brpanel whoami mostra qual servidor está ativo). Para entrar sem digitar, por exemplo em um agente: printf '%s' 'brp_…' | brpanel login ENDEREÇO --token-stdin.

Um token dá o mesmo poder que esta tela (publicar e apagar aplicações e bancos): trate como senha, um por computador ou agente, e revogue o que não usa mais.

Para agentes de IA

Cole este bloco no prompt do sistema de qualquer agente. Ele funciona até com modelos pequenos (4B): são poucas regras, e cada resposta do comando começa com OK: ou ERRO: e traz linhas DICA: com o próximo passo. Erros de digitação sugerem o comando certo (você quis dizer…).

Como as respostas funcionam

OK: …
deu certo (código de saída 0)
ERRO: …
falhou: código 1 se o painel recusou, 2 se o comando foi escrito errado
DICA: …
o próximo passo; USO: e EXEMPLO: mostram a forma certa
--json
qualquer comando responde em JSON
--yes
obrigatório nos comandos que apagam dados; sem ele nada é apagado
--wait
o deploy roda em segundo plano; com --wait o comando espera e diz se deu certo
